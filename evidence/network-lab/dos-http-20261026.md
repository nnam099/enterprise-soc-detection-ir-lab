# HTTP Load / Availability Test — 2026-10-26

**Objective:** Measure the availability impact of a controlled HTTP load against the lab target from the Parrot host on `Vung_LAN`.

**Result:** Availability degraded — **~20× response time** under 200 concurrent clients, with full recovery after the load stopped. No request failures at this level.

---

## Setup

| Role | Address | Tool |
|---|---|---|
| Attacker | Parrot host `10.0.0.254/24` | ApacheBench (`ab`) |
| Target | Metasploitable 2 `10.0.0.5/24` | Apache 2.2.8 |

`hping3` could not be used: raw sockets require `CAP_NET_RAW`/root, and the test account does not have it (`socket: Operation not permitted`). ApacheBench is an application-layer load generator and requires no elevation.

---

## Results

| Phase | Requests | Concurrency | Req/sec | Time/request | Failed |
|---|---|---:|---:|---:|---:|
| Baseline | 200 | 10 | 172.84 | **57.9 ms** | 0 |
| Load (10 s) | 1,751 | 200 | 174.95 | **1,143.2 ms** | 0 |
| Recovery | 100 | 10 | 172.41 | **58.0 ms** | 0 |

During the load, direct `curl` requests took **0.74–1.04 s** versus **~6 ms** at baseline.

```text
Baseline curl:  200 0.006356 / 0.006258 / 0.006084
During load:    200 0.745866 / 0.773805 / 0.786789 / 0.736079 ...
                200 1.035705 / 0.868553 / 0.956185 / 0.826876
After:          ping 0% loss; ab back to 58 ms
```

---

## Analysis

- Throughput stayed flat (~175 req/s), but **latency increased ~20×**. The target's request-processing capacity is saturated; clients wait in the connection/queue.
- No failed requests at 200 concurrent clients, so this is **degradation**, not a full outage. Higher concurrency, slowloris-style partial requests, or a SYN flood would be needed to cause an outage.
- The service recovered immediately after the load stopped, with no restart.
- Because the attacker is inside `Vung_LAN`, the firewall does not mitigate this. Controls must be host/application-level or IDS/IPS-based.

**Mitigations to discuss:** connection/rate limits, `mod_reqtimeout`, load balancing, WAF/IPS, monitoring latency SLOs.

## Limitations

- Application-layer HTTP load only; no raw-packet SYN flood (permission) and no slowloris.
- Single attacker host; no botnet/distributed traffic.
- No IDS or firewall mitigation was active during the test.
- Target is a deliberately vulnerable lab VM; results do not generalize to production.
